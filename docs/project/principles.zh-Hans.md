# 原则

这些文档里的每条规则都来自下面某一条。遇到规则没覆盖的情况，就按这些原则和[目标](about.md#目标)来判断：一个运行高效、容易参与、速度优先的 remote。

1. **只用开发者自己的构建。**应用来自开发者的官方下载，在你的电脑上安装时才下载（extra-data）。FlatPark 从不重新构建应用，也从不托管它的文件。必须从源码构建的应用，在它自己公开的 `-release` 仓库里构建，产出的 release 和其他下载一样使用。
2. **开源应用原样运行。**不向它的进程注入任何东西，不改它的任何文件。如果它不这样做就没法在沙箱里工作，应该由上游修复，修好之前不上架。
3. **闭源应用的改动要公开说明。**闭源应用可能需要改动才能在沙箱里工作；如果有，它的页面会写清改了什么、为什么。
4. **每个软件包都说明自己做了什么。**每个包都申报自己的打包级别（原样、有适配、有改动、隔离降低），CI 会把申报和软件包的实际行为对照检查。
5. **默认最小权限。**软件包只授予应用主要功能所需的权限；更多的权限由用户自己决定，以命令的形式写在页面上。
6. **开发者对自己的应用有最终决定权**：要不要上架、怎么打包、怎么介绍。对其他应用没有特权。
7. **看软件包本身，不看它是怎么写出来的。**应用能不能上架，看它做了什么、怎么打包，不看它是不是用 AI 写的。
8. **整个目录只用一个 runtime 版本。**所有应用一起升级到新版本，用户的磁盘上只留一份。
9. **上线前测试，上线后快速修复。**我们自己的改动在上线前测试（[测试手册](../reviewers/testing-playbook.md)）；上游的新版本立刻上线，出了问题就快速修。
10. **决策公开。**规则、软件包、审核、事故和下架，全都在公开的仓库里。
